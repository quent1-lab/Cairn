# Cairn — instructions pour Claude

Simulateur d'évolution culturelle et technologique **émergente** : monde infini procédural, humains simulés individuellement, serveur Rust persistant 24/7, client web WASM pixel-art, joueur-divinité (Foi, interventions ambivalentes), Chronique narrative.

**Référence obligatoire : [docs/BRIEF.md](docs/BRIEF.md)** — vision, systèmes, architecture cible, plan en 6 phases avec critères d'acceptation. À consulter avant toute décision de conception.

## Contexte de travail

- Projet d'**apprentissage Rust** + pièce de portfolio (étudiant ingénieur, fort en C/C++/embarqué, Rust en cours d'acquisition).
- Répondre **en français**. Expliquer les idiomes Rust nouveaux dans la réponse (pas en commentaires tutoriels dans le code — les commentaires du code documentent le domaine, pas le langage).

## Règles non négociables (BRIEF §0 et §11)

1. **Émergence stricte** : aucun comportement narratif scripté. Les « âges » sont des étiquettes dérivées, jamais des conditions de déblocage.
2. **Aucune dépendance sans justification** face à une implémentation maison de ~50 lignes.
3. Simple et lisible d'abord ; **optimiser seulement après mesure**.
4. **Déterminisme bit-à-bit** : RNG dérivé de la seed globale (`cairn-core`), jamais d'itération sur `HashMap` dans la simulation.
5. Chaque incrément produit quelque chose de **visible et testable**.

## Architecture

Workspace cible (BRIEF §8) : `crates/{core, worldgen, sim, protocol, server, client}` — `protocol` partagé serveur↔client. Existent : `core`, `worldgen`, `sim`.

`sim` = monde **chunké** (store de tuiles) : le pont entre worldgen (baseline pur, immuable) et l'état mutable à venir. `Tile` (16 o) matérialise le baseline + slots mutables (fertilité, biomasse) ; `Chunk` 64×64 généré à la demande (humidité échantillonnée aux 4 coins partagés → aucune couture) ; `World` = LRU BTreeMap, capacité bornée, éviction sûre car régénérable. Le store sert le **local** ; la vue monde lit le worldgen en échantillonnage grossier (mode carte). **Règle : worldgen reste pur ; l'évolution/mutation vit dans `sim`.**

## Échelle

**1 tuile = 2 m** (échelle humaine : une hutte = plusieurs tuiles, un agent sur une, un village se parcourt tuile à tuile). Source unique : `core::scale` (`TILE_METERS`, `km_to_tiles`, `tiles_to_km`). Tout le worldgen exprime ses tailles en km via ces helpers. Le monde est donc énorme en tuiles (continents ~3000 km ≈ 1,5 M tuiles) — sans coût car procédural/chunké. Le zoom monde↔village est un problème de **rendu (LOD)**, jamais de taille de tuile : proche = sprites/structures, loin = mode carte agrégé.

## Commandes

- `cargo check` / `cargo test` — vérification et tests.
- `cargo run --release -p cairn-sim --example life_demo -- [seed] [années] [agents]` — démo Phase 2 : population lâchée dans un foyer tempéré, rapport mensuel (pop, morts par cause, besoins moyens), verdict face au critère d'acceptation, carte PNG `out/life_<seed>.png` (centrée sur la médiane des survivants).
- Client : `cargo run --release -p cairn-client --example preview -- <couche> <km>` rend le canvas en PNG (vérif sans navigateur). Bundle web : `crates/client/build.sh` (nécessite `wasm-bindgen-cli` — voir note d'env).
- `cargo run --release -p cairn-worldgen --example map_png -- <seed> [tuiles/pixel]` — rend une image PNG par couche du pipeline dans `out/` (`_alt`, `_temp`, `_hum`, `_bio`) + % de terres émergées ; 2ᵉ arg = zoom (petit = gros plan). Toujours en `--release`.
- `cargo run --release -p cairn-worldgen --example analyze -- [nb_seeds] [onde_continent] [sea_bias]` — vérifs statistiques : connexité des masses terrestres + preuve du rain shadow (humidité par barrière au vent).
- **git : uniquement via Git Bash** — absent du PATH PowerShell. Les commits sont gérés par Claude (demande explicite de l'utilisateur), messages en français, style conventional commits.

## État d'avancement

- **Phase 2 EN COURS — incréments 1 (« cœur battant ») et 2 (« la faune ») faits** : `hecs` acté (arbitrage §10.2 avec l'utilisateur : ECS minimaliste, ordonnancement des systèmes écrit par nous → déterminisme explicite ; salts sim = plage 1000+). **Temps** : 1 tick = 1 h, année de 360 j (`core::time`, `SimTime`) ; un tick est un *budget* d'une heure (marche jusqu'à ~2 km puis action). **Climat instantané** (`sim::climate`) : saisons par **latitude signée** (`Latitude::signed_fraction`, onde triangulaire de période double → bandes nord/sud alternées, continue partout, hémisphères opposés) + cycle jour/nuit amorti par l'humidité ; la croissance végétale gèle sous 5 °C. **Physiologie** (`sim::agent`) : faim/soif/fatigue/froid/santé/mort, constantes lisibles par heure, dérive pure testable. **Utility AI minimale** (`sim::brain`, `sim::curves`) : courbes de réponse (linéaire/puissance/logistique/exponentielle), softmax τ=0,12, tâches persistantes (boire, fourrager, **chasser**, dormir, s'abriter, errer), délibération bucketée /4 ticks + bonus d'engagement. **Écologie** (`sim::ecology`) : repousse logistique en **forme fermée** (LOD temporel §8.2), arrondi stochastique (u8), banque de graines (P=0 repart de 1), quotidienne sur les seuls chunks sales. **Eau douce** : sources ponctuelles = proxy d'hydrologie assumé, **cache de sources par chunk sans matérialisation** (`chunk::springs_for`, préfiltre par hachage — leçon perf : matérialiser des chunks pour chercher l'eau écroulait le LRU). **Mutation** : `World::tile_mut` marque le chunk sale ; éviction **bornée en deux temps** (propres d'abord, sales à contrecœur sous pression max — un chunk sale évincé se régénère au baseline = rattrapage analytique de la repousse ; la mémoire reste bornée quoi qu'il arrive).

  - **Faune** (`sim::fauna`, monde `hecs` **séparé** des humains — `Position` partagé, coordination par instantanés `HerdView`) : **l'entité est le troupeau/la meute, pas l'animal** (effectif continu `f32` → Lotka-Volterra gratuit + steering au niveau du groupe). Troupeaux : machine à états (pâture/fuite/migration), démographie sur la **satiété** (natalité ∝ herbe broutée, capacité de charge *émergente*, jamais écrite en dur), pâture au **steering de gradient** (viser la tuile la plus verte à ±160 m, **ex æquo départagés au hasard** → marche diffusive ; sinon dérive balistique — bug mesuré : tous les troupeaux filaient plein est à 1,9 km/j), fission > 90 têtes, mort < 4. Meutes : équation prédateur (croît des prises, s'éteint sans gibier). **Chasse humaine** : tâche `Hunt` scorée comme la cueillette mais bien plus nourrissante ; réussit par **épuisement** — la bête galope plus vite que l'homme mais pas plus longtemps (souffle `FLEE_COOLDOWN`), sans quoi aucune chasse n'aboutissait. **Validation seed 42** (100 agents, 1 an, 49 troupeaux + 4 meutes) : récit émergent complet — surchasse → gibier 1225→0 en 4 mois, **boom-bust des prédateurs** (20→67→0, Lotka-Volterra), humains 90/100 survivants en se rabattant sur la cueillette. **Critère « surchasse → effondrement local observable » rempli** (test contrôlé : 60 chasseurs vident 3 km, témoin sans chasseur stable). **Observation de calibrage** : 100 chasseurs concentrés épuisent une population de gibier bornée — correct et sur-thème ; la coexistence durable suppose une densité de chasseurs plus faible ou un afflux de gibier (monde infini).

  **43 tests sim verts, déterminisme bit-à-bit testé (humains + faune + prises)**. Perf : ~10 ticks/s avec 100 agents + faune (capacité 16384 pour couvrir le plateau ~8500 chunks sales de la scène).

  - **Client vivant** (`cairn-client`, WASM) : le client **fait tourner un `Sim` localement** (le serveur viendra en Phase 6). Boucle `requestAnimationFrame` permanente : chaque frame avance la sim selon le temps réel × vitesse, peint le terrain (worldgen, **mis en cache** — ne recalcule qu'au pan/zoom), puis dessine agents et faune par-dessus en canvas 2D (carrés pixel-art ; troupeaux fauve, meutes violet). **Interpolation d'affichage** (§8.5) : chaque entité est rendue entre sa position au tick précédent (`prev_pos`/`prev_fauna`, par ID stable) et sa position courante selon `render_alpha` — sans quoi les bonds d'une heure de jeu (jusqu'à 4 km/tick) se voyaient comme des téléportations. **Mode de couleur des humains** commutable : par activité (en chemin/mange/boit/dort/s'abrite) ou couleur fixe. Panneau à **deux onglets** : *Carte* (couches + pause/vitesse ×1/×4/×16 + « Suivre la population » + légende + bandeau date/effectifs) et *Paramètres* (seed, humains initiaux, densité de gibier → **Régénérer** ; + **placement manuel** : armer « Poser des humains », cliquer la carte dépose une bande, le gibier se génère autour). Mode **Suivre** = cadrage à hystérésis sur la boîte englobante de la population (centre + zoom, plafonné) — indispensable car en Phase 2 (sans clans) le groupe **diffuse librement** sur des km. Hooks URL `?ticks=N` (pré-avance la sim) et `?static=1` (rend une frame puis s'arrête, pour capture). `Sim::with_config`/`World::with_config` (humidité rapide) ; scène mutualisée dans `sim::scenario` (`find_home`/`populate`/`drop_band`). Vérif : exemple natif `client_render` (même code de rendu → PNG) + WASM confirmé actif en navigateur (sim live dans le DOM). **Note env : le canvas 2D ne se capture pas en Edge headless ici — vérifier le rendu via `client_render` ou un vrai navigateur.**

  - **Pathfinding A\* budgété** (`sim::pathfind`, BRIEF §8.2) : A* sur **grille de nav grossière** (cellules de `NAV_STRIDE=16` tuiles), coûts entiers (×1000, déterministe), heuristique octile consistante, budget de nœuds (`NODE_BUDGET=2500`) → au-delà, **meilleur chemin partiel**. Franchissabilité **mise en cache par cellule** (sans quoi chaque cellule était re-testée jusqu'à 8× = évaluations fBm inutiles). Intégration (`sim.rs`) : **ligne droite d'abord** (cas courant, gratuit), A* **seulement quand l'eau bloque** ; `Route` persistante par agent (table à côté de l'ECS, `Behavior` reste `Copy`), budget `PATH_REQUESTS_PER_TICK=8`. L'**errance vise la terre** (marche le long du rayon jusqu'au dernier point ferme) → supprime la cause n°1 d'A* inutile. Mesuré : ~3 appels A*/400 ticks sur la scène côtière (le pathfinding n'est PAS le coût dominant — c'est le churn de chunks de la dispersion). Test d'intégration : un agent au bord de l'eau **contourne** (crée une route, se déplace, reste sur terre) au lieu de se figer. Compteur `Sim::path_calls`.

  - **Calibrage (banc `example calibrate`)** : lâche la population dans des foyers de climats différents (tempéré / frais / froid, cherchés par `scenario::find_home_where`) sur plusieurs seeds, mesure la mortalité **par cause** + le **% de temps passé à s'abriter** (`Sim::shelter_ticks`). Résultat sur 3 seeds × an complet (fast config) : **8 scénarios sur 9 survivent** avec mortalité partielle. Le **% d'abri croît avec le froid** (0 % en tempéré → 2-10 % en froid) : le critère « s'abritent quand il fait froid » est **prouvé et gradué**. La survie au froid **bascule autour de 0 °C** : au-dessus (frais 3-5 °C, froid ~1-2,5 °C) → survivable avec abris et quelques morts de froid ; en dessous (taïga -0,6 °C) → extinction par hypothermie. Cette extinction est **assumée et réaliste** : des humains **sans feu ni vêtements** ne passent pas un hiver de taïga — c'est la pression qui motivera le feu en Phase 5. (Bug corrigé au passage : `populate` débordait le nombre d'agents visé — `break` n'échappait que la boucle interne.)
